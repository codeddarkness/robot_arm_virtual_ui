# Robot Arm Virtual UI - Project Handoff

## Project Overview

This document provides a comprehensive overview of the Robot Arm Virtual UI project for handoff to another development team. The project consists of a web-based 3D interface for controlling a 4-Degree-of-Freedom (4DoF) robot arm, with both stable and development versions.

## Technical Details

### Robot Arm Configuration

The robot arm has 4 servos (4 Degrees of Freedom):
- Channel 0: Base rotation (Y-axis, left/right)
- Channel 1: Lower arm joint (Z-axis, up/down)
- Channel 2: Upper arm joint (Z-axis, up/down)
- Channel 3: Gripper rotation (Y-axis, left/right)

Each servo has a range of 0-270 degrees, with 135 degrees as the center position.

### Control Mechanisms

1. **Sliders**: Direct control of each servo angle
2. **Joysticks**:
   - Left joystick: X controls channel 0, Y controls channel 1
   - Right joystick: Y controls channel 2, X controls channel 3

3. **Preset Buttons** (Dev version only):
   - Move Left [000]: Sets all servos to 0 degrees
   - Center [135]: Sets all servos to 135 degrees
   - Move Right [270]: Sets all servos to 270 degrees

4. **Random Movement** (Dev version only):
   - Generates 10 random positions
   - Smooth transitions between positions
   - 1-second hold at each position

### Animation System

The development version uses a sophisticated animation system:
- Target angles and current angles are tracked separately
- Smooth transitions between positions with configurable speed
- Timing controls for holding at positions

### MPU6050 Simulation (Dev version only)

A virtual MPU6050 sensor attached to servo/channel 3 provides:
- Accelerometer readings (X, Y, Z) based on orientation
- Gyroscope readings (X, Y, Z) with simulated movement

## API Endpoints

- **GET /api/servo**: Retrieves current servo positions
- **POST /api/servo**: Updates servo positions
- **GET /dev**: Accesses development version

## Development Process

The project follows an iterative development approach:
1. New features are added to the development version
2. Features are tested and refined
3. Stable features are backported to the stable version

## Development Guidelines

### Coding Standards

- **JavaScript**: ES6 syntax with clear function names and comments
- **Python**: PEP 8 style guide with descriptive variable names
- **HTML/CSS**: Semantic elements with BEM-like class naming

### File Structure

- Keep stable and development versions in separate directories
- Use the existing directory structure for consistency
- Place new static assets in the appropriate /static or /static/dev directory

### Versioning

Version numbers follow the format: `vX.Y.Z-N` where:
- X: Major version (significant changes)
- Y: Minor version (new features)
- Z: Patch version (bug fixes)
- N: Build number

### Contribution Workflow

1. Create a backup of the current code
2. Make changes in development version first
3. Test thoroughly before updating stable version
4. Document all changes

## Key JavaScript Functions

- `initScene()`: Sets up the Three.js scene
- `createRobotArm()`: Creates the 3D robot arm model
- `updateArmPosition()`: Updates the arm position based on servo angles
- `animateToTarget()`: Animates movement to target position
- `initJoysticks()`: Sets up joystick controls
- `initSliders()`: Sets up slider controls
- `initButtons()`: Sets up buttons and additional controls

## Key Python Functions

- `app.route('/')`: Main route for stable version
- `app.route('/dev')`: Route for development version
- `get_servo_positions()`: API endpoint to get servo states
- `update_servo_positions()`: API endpoint to update servo states
- `find_available_port()`: Finds an available port for the web server

## Troubleshooting

- **Port conflicts**: The application will automatically select the next available port
- **Flask dependency issues**: Make sure to use compatible versions as specified in requirements.txt
- **3D rendering issues**: Check browser WebGL support
